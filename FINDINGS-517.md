browser UA, okhttp UA, and no UA all behave identically).

| probe | status | unique post ids | overlap with page 1 |

## Homepage pagination — provider side: BROKEN (root cause found)

`Eroticmv.kt` `getMainPage`:

```kotlin
val url = if (page > 1) "$mainUrl/page/$page/" else request.data
```

CloudStream calls `getMainPage(page, request)` **per row**. This branch ignores
`request.data` when page > 1, so on page 2 every one of the 75 facet rows also fetches
`/page/2/` of the homepage and answers with homepage page-2 cards under _facet row names_
(country japan, genre bdsm, …). Result in-app: duplicate/global-dedupe noise swamps the
pager, and the "Latest Erotic Movies" row degrades to effectively no pagination. The
report's symptom matches exactly.

Facets are 1-page by site design (FINDINGS-497: `/page/2/` and `?paged=2` both 404 on
facet URLs) — the fix is: facet row + page > 1 ⇒ empty page, `hasNext = false`. Latest
row keeps `/page/N/`.

| `GET /?s=asian&paged=2` | 404 |
| `GET /search/asian/page/2/` | 404 |

Search results page contains no `link rel=next` and no `page-numbers`/`nav-links` markup.

Search = 1 page; nothing to fix there.

## Fix

Extract pure companion `homeUrlFor(data, page): String?` — null ⇒ page doesn't exist
(facet + page>1) — with JUnit tests (red→green), and gate `getMainPage` on it.
